Alternativa descoberta: ajustar o threshold de decisão é muito mais eficaz que reamostragem quando se tem um bom classificador base.
Experimento 3 ✓ Keep F1 0,836 ▲ +6,7%

Precisão: 0,986 Recall: 0,726 Threshold ótimo: 0,99 TP/FP/FN: 69/1/26

Ao subir o threshold, a precisão dispara para 0,986 (apenas 1 falso positivo), mas o recall cai para 0,73 (26 fraudes não detectadas). O F1 sobe de 0,784 para 0,836.

O scale_pos_weight já estava bem calibrado com o valor padrão (neg_count / pos_count).
Experimento 5 ✓ Keep F1 0,851 ▲ +1,8%
Feature engineering: interações Amount×V, Amount_log, Amount², Time cíclico, quantis de Amount

💡 Insight chave: Features de interação Amount×V são altamente informativas. As features V1–V28 já são PCA-transformadas e anônimas, mas interagi-las com Amount (a única feature numérica interpretável) cria sinais poderosos. O threshold ótimo caiu de 0,99 para 0,75, indicando que o modelo agora produz scores de probabilidade mais discriminativos.

A queda de precisão (0,986 → 0,937) é compensada pelo ganho em recall (0,726 → 0,779), resultando em F1 maior e um modelo que detecta mais fraudes reais.

💡 Insight chave: XGBoost e LogisticRegression cometem erros diferentes. Como ambos melhoraram simultaneamente (precisão +1,3pp e recall +0,9pp), os erros de um modelo são compensados pelo outro. A regressão logística captura relações lineares que o XGBoost pode ignorar devido ao viés de árvore. PR-AUC também subiu (0,825 → 0,835).

Experimento 7 ✗ Discard F1 0,862 (=)
Otimização de peso do ensemble (grid search): confirmou W=0.5 como ótimo
🔍 Verificação útil: O grid search de pesos confirmou que a média simples (0.5/0.5) já é o blend ótimo. As distribuições de probabilidade dos dois modelos já estão bem calibradas entre si — nenhum modelo domina o outro em precisão.
Experimento 8 ✗ Discard F1 0,843 ▼ -2,3%
Ensemble de 3 modelos (XGB + LR + RandomForest)
Precisão: 0,904 Recall: 0,789 Train: 26,5s (8× mais lento)
💀 Lição #3: Nem todo ensemble agrega valor — diversidade real entre modelos importa. RandomForest e XGBoost são ambos ensembles de árvores e cometem erros correlacionados. Em vez de complementar, o RF introduziu ruído, degradando a precisão do ensemble. Além disso, o treino ficou 8× mais lento (26,5s vs 4,8s).

Critério prático: Para ensemble funcionar, os modelos precisam ter arquiteturas fundamentalmente diferentes (árvore + linear, como XGB + LR).
Experimento 9 ✗ Discard F1 0,846 ▼ -1,9%
Cross-validation (5-fold) para seleção de threshold
Precisão: 0,925 Recall: 0,779 Threshold CV: 0,89 (vs 0,85 single-split)
💀 Lição #4: Cross-validation pode diluir o sinal com classes raras. O threshold via CV foi mais conservador (0,89 vs 0,85), resultando em pior F1. Em cada fold do CV, a proporção de fraudes varia, fazendo a média dos thresholds tender a valores subótimos. Para dados extremamente desbalanceados, um único split de validação bem estratificado pode ser mais eficaz que CV.

🚫 Becos sem Saída (O que NÃO funciona)

❌ SMOTE / Oversampling sintético
Gera exemplos irreais a partir de apenas 378 fraudes. O modelo classifica tudo como fraude. Precisão cai para 0,30.
❌ Aumentar complexidade do modelo (árvores mais profundas)
Overfitting nos poucos exemplos positivos. Recall e F1 pioram. O modelo base já é adequado.
❌ Adicionar RandomForest ao ensemble
Modelos de mesma família (árvores) são correlacionados demais. RF adiciona ruído, não sinal.
❌ Cross-validation para escolha de threshold
A média entre folds dilui o sinal. Um split estratificado simples é melhor para classes ultra-raras.
❌ Otimizar peso do ensemble além da média simples
Para XGB + LR, 0.5/0.5 já é o blend ótimo. Grid search não encontrou peso melhor.

💡 Insights Fundamentais

🔑 Threshold > Reamostragem

Em dados extremamente desbalanceados, ajustar o threshold de decisão é muito mais eficaz que SMOTE ou undersampling. O threshold padrão 0.5 é arbitrariamente ruim — o ótimo está em 0.85–0.99 dependendo do modelo.

🔑 Features de interação com Amount

Mesmo com features PCA-anônimas, interagi-las com Amount (a única feature interpretável) gera sinais discriminativos fortes. Isso reduz o threshold ótimo (scores mais confiáveis) e melhora recall.

🔑 Ensemble heterogêneo funciona

Combinar XGBoost (não-linear, árvores) com LogisticRegression (linear) captura padrões complementares. Ambos precisão e recall melhoram simultaneamente — sinal claro de diversidade real entre os modelos.

🔑 Simplicidade vence com poucos dados

Com apenas 378 fraudes para aprender, modelos mais complexos (árvores profundas, ensembles de 3+ modelos, CV) tendem a overfitar ou diluir o sinal. O modelo base com boas features e threshold tuning já vai longe.

🔑 Métricas de desbalanceamento importam

Acurácia (99,9%) é inútil aqui — um modelo que diz "não fraude" para tudo tem 99,8% de acurácia. F1 da classe minoritária, PR-AUC e a matriz de confusão (TP/FP/FN) são as métricas que realmente importam.

🔑 Scale_pos_weight é suficiente

O parâmetro scale_pos_weight do XGBoost (razão neg/pos) já lida bem com o desbalanceamento internamente, sem precisar de reamostragem externa. Dobrar o valor não trouxe benefício.
